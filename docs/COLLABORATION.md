# 경제사 협업 편집 — 2026-09-10

2026-11-20 공통 규약: [표준 저장 아키텍처](STORAGE-ARCHITECTURE.md). 기존 입력 확정·충돌 비교·저장 이력은 유지한다. 반복 동기화는 활성 페이지·온라인·보이는 탭에서만 5초 주기로 실행하며 숨김/메뉴 이탈에서는 멈추고 복귀 시 즉시 확인한다. 최신 클라이언트는 `/collab/sync` 한 요청으로 버전 확인과 접속 신호를 보내며 접속 기록은 15초에 한 번만 쓴다. 구버전 state/presence 경로는 유지한다. 국제 연표는 사건별 `intl:` 리소스로 같은 저장 큐·이력·충돌·기기 복구를 사용한다.

2명이 여러 창에서 편집할 때의 내용 손실을 줄이는 업데이트입니다. 자본주의 경제사의 사건 카드·노드·사건 인사이트·메타 카드를 대상으로 합니다. 보류 중인 종목 기능과 기존 보안·인증 정책은 변경하지 않습니다.

## 사용법

1. 배포 뒤 기존 창은 작성 중인 내용을 별도 보관하고 새로고침합니다. 구버전 창의 저장은 428로 거절됩니다.
2. 이름 지정 없이 바로 편집합니다. 각 창을 자동으로 구분하며, 다른 창이 접속해 있을 때만 개수를 표시합니다. 변경 이력에는 자동 생성된 창 식별자가 남습니다.
3. 노드 본문·메모·표 셀/제목·사건 제목은 **칸 밖을 클릭하거나 Tab으로 이동할 때** 저장됩니다. 타이핑 중에는 해당 컴포넌트의 초안만 변경하고 전체 카드 캐시·IndexedDB·서버 저장은 호출하지 않습니다. 인사이트는 기존 자동 저장을 유지합니다. 날짜·기간은 날짜 패널 밖으로 이동하거나 **저장** 버튼으로 확정하고, 표 너비는 드래그를 끝내야 저장됩니다.
4. 다른 칸·필드뿐 아니라 같은 문장·표 셀 안의 **서로 다른 표현 수정도 자동 병합**합니다. 실제로 겹치는 수정은 **수정 전 원문 / 내 수정 / 다른 편집자 수정**의 문장으로 한 곳씩 확인합니다. 겹친 표현은 노란색으로 표시합니다. 문장을 선택하면 다음 곳으로 넘어가며, **이전**으로 돌아가도 선택과 직접 입력이 남습니다. **직접 표현을 써서 합치기**에서 문장을 작성하고 **이 문장으로 선택**할 수도 있습니다. 마지막에 **선택한 내용 저장**을 누릅니다. 이때 자동으로 합칠 수 있던 다른 표현은 양쪽에서 보존합니다. 삭제된 항목을 되살리는 경우에는 복원을 별도로 체크합니다.
5. 저장 실패는 **저장 다시 시도**를 누릅니다. 새로고침 후 남은 초안은 **서버와 비교해 복구**를 누릅니다. 서버와 같은 요청 ID를 재사용해 응답만 유실된 저장을 중복 적용하지 않습니다.
6. **변경 이력**에서 저장한 창·시간·이전/이후 값을 확인하고 **이 변경만 되돌리기**를 사용할 수 있습니다. 이후 다른 사람이 같은 부분을 바꾸었으면 다시 충돌 비교를 거칩니다. 삭제된 카드의 이력도 조회 가능합니다. 업데이트 전 이력에 기록된 이름은 그대로 보존합니다.

## 병합 단위

| 동시에 편집한 내용 | 처리 |
|---|---|
| 다른 사건·다른 노드 | 각 변경 보존 |
| 같은 노드의 본문 / 메모 / 표 | 서로 다른 필드는 병합 |
| 같은 카드의 제목 / 노드 / 사건 인사이트 | 서로 다른 필드는 병합 |
| 다른 메타 카드, 같은 메타 카드의 제목 / 본문 | 변경 필드 병합 |
| 같은 문장·같은 표 셀의 서로 다른 표현 | 기준 원문에서 바뀐 구간을 비교해 병합 |
| 같은 표의 다른 셀, 열 추가와 기존 셀 수정 | 표 머리글·행과 원문 위치가 명확하면 함께 보존 |
| 같은 본문·표의 서로 겹치는 표현 | 해당 문장을 한 곳씩 선택하거나 직접 작성 |
| 블록 삽입과 기존 블록 수정 | 순서상 대응이 명확하면 병합. 모호한 이동·삭제는 선택 |
| 독립적인 노드 추가·삭제 | 안정적인 노드 키를 기준으로 병합 |
| 같은 항목 삭제와 수정, 서로 다른 순서 재배치 | 충돌 확인 |

서버가 트랜잭션 잠금 안에서 최신 문서의 필드 값을 검사합니다. 충돌이 하나라도 있으면 요청 전체를 거절하고 연구 데이터와 이력을 모두 변경하지 않습니다. 성공 시 변경한 행과 실제 변경 이력을 함께 기록합니다. 기존 노드 ID는 유지합니다. 전체 카드/메타 배열을 마지막 요청으로 덮어쓰는 저장 경로는 브라우저에서 막았습니다.

클라이언트는 카드별 요청을 직렬화합니다. 진행 중 요청의 ID와 내용을 고정하고, 응답을 기다리는 동안의 추가 입력은 응답의 최신 문서에 다시 적용합니다. 기기 초안에는 비교 기준·작성본·전송 요청을 함께 보관합니다. IndexedDB 기록 실패는 별도로 알립니다.

텍스트 비교는 낱말·숫자 단위입니다. `20 → 25`와 `20 → 30`을 잘못 섞어 `35`로 만들지 않습니다. 리치텍스트의 색상·강조·링크 표식을 보존하고, 표식이 겹쳐 깨질 수 있으면 사용자에게 선택을 요청합니다. 문장 선택의 두 후보에는 같은 문장 안의 독립 수정도 이미 포함됩니다. 동일 문장 안의 여러 충돌은 한 문장으로 함께 판단하며, 양쪽 표현을 섞으려면 직접 작성합니다. 블록이 원본인 카드의 검색용 text/tables/images 미러는 합친 블록에서 다시 생성해 같은 수정에 두 번 답하지 않습니다. 기반 원문 없이 양쪽이 다른 새 내용으로 만든 경우나, 배열의 대응·삭제가 모호한 경우에는 구조 전체의 확인이 남을 수 있습니다.

## 운영과 한계

- 활성 페이지에서 다른 창의 변경은 약 5초마다 확인합니다. 접속 기록 갱신은 15초, 만료는 45초입니다. 숨김/오프라인/다른 메뉴에서는 정기 조회를 멈추고 복귀 때 즉시 재개합니다. 접속 표시는 강제 편집 잠금이 아닙니다.
- 기기 저장소 삭제, 비공개 창 종료, 디스크 오류 뒤의 미저장 초안 복구까지 보장하지 않습니다. 서버 저장 완료 여부를 확인하고 기존 전체 백업도 유지합니다.
- 칸을 벗어나기 전의 입력은 메모리에만 있습니다. 브라우저 강제 종료나 기기 전원 차단까지 복구를 보장하지 않습니다. blur 이후에는 기존 IndexedDB 초안·재시도·충돌 비교를 사용합니다.
- 전역 화살표는 기존 개별 추가/삭제 API를 유지합니다. 위험했던 전체 링크 스냅샷 Undo는 화면에서 제외했습니다. 본문·표·카드 협업 이력에 화살표 편집은 포함되지 않습니다.
- 새 이력은 업데이트 이후 성공한 저장부터 기록됩니다. 이전 `cap_history` 스냅샷 및 로컬 백업은 보존하며 기존 CLI로 조회합니다. 기존 관리 스크립트의 직접 DB 쓰기는 협업 잠금을 우회하므로 공동 편집 중 실행하지 않습니다.
- 요청 ID 중복 방지를 위해 `cap_edit_operations`를 자동 삭제하지 않습니다. 이미지가 포함된 필드의 변경 이력은 용량이 커질 수 있습니다. 이력 정리 정책은 추후 별도로 설계합니다.
- 운영 반영 순서: `cap:backup` → 검증 → `cap:collab:init`(테이블 2개 추가만) → 배포 → `cap:integrity` 및 읽기 확인. 공유 Supabase에 `drizzle-kit push`를 사용하지 않습니다.
