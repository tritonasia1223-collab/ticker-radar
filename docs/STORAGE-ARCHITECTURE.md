# 웹앱 표준 저장·동기화 아키텍처

2026-11-20 사용자 승인. 신규 편집 페이지는 이 문서를 기본 규약으로 적용한다.

## 책임 분리

- 화면 입력은 즉시 반영한다. 서버 왕복을 타이핑 경로에 넣지 않는다.
- DB가 확정본이다. IndexedDB는 비교 기준·작성본·고정된 전송 요청을 보관하는 복구용 저널이다. 기기 보관과 서버 저장 완료 상태를 구분한다.
- 저장은 변경 필드만 전송한다. 리소스별 요청 한 개만 진행하며, 전송 중 추가 입력은 성공 응답에 재적용해 다음 요청으로 보낸다.
- 서버는 트랜잭션 안에서 최신 필드와 before 값을 비교한다. 독립 필드 병합, 동일 필드 충돌 표시, 요청 ID 재시도 멱등성을 보장한다. 조용한 마지막 요청 덮어쓰기는 금지한다.
- 삭제도 비교·이력·복구 대상이다. 삭제와 수정이 경합하면 충돌로 처리한다.

## 입력과 저장 시점

기존 경제사 칸은 blur/Tab 확정, 인사이트는 저장/Ctrl+S/패널 전환 확정을 유지한다. 새 자동 저장 편집기는 화면 입력을 즉시 반영하고 기기 초안을 기록한 뒤 600~1000ms idle에 서버 저장한다. 국제 연표는 편집기의 200ms 입력 버퍼와 저장기의 600ms 모으기를 사용한다. blur·페이지 이동·숨김은 버퍼의 마지막 입력을 즉시 확정하고 저장을 요청한다. 종료 직전 네트워크 성공은 보장하지 않으므로 미저장 경고와 다음 접속 복구를 제공한다.

## 동기화 생명주기

페이지가 소비자 등록/해제한다. 소비자가 있고 온라인이며 탭이 보일 때만 5초 주기 조회를 실행한다. 숨김/페이지 이탈/오프라인에서는 반복 조회를 중단하되 저장 큐·초안·이미 진행 중인 쓰기는 유지한다. 복귀·재연결 시 한 번 즉시 확인한다. 한 요청 진행 중 중복 조회는 합치며, 이전 페이지 응답은 세대 번호로 무효화한다.

조회와 접속 신호를 단일 요청으로 보낸다. 접속 기록은 최대 15초에 한 번 갱신하고, 화면에는 45초 내 신호만 표시한다. 접속은 안내이며 잠금·저장 권한이 아니다. 구버전 state/presence 경로는 호환을 위해 유지한다.

Vercel에서는 Supabase 공유 풀러의 **트랜잭션 모드(6543)**를 사용한다. 같은 host·DB·사용자·자격증명을 유지하고, 확인된 Supabase 공유 풀러의 세션 포트 5432만 런타임에서 바꾼다. 일반 DB 주소와 로컬/관리 스크립트의 세션 연결은 자동 변경하지 않는다. `prepare:false`, 요청 내 `max:1`, `idle_timeout:5`, `connect_timeout:5`를 유지한다. 저장 잠금은 반드시 트랜잭션 범위 잠금(`pg_advisory_xact_lock`)을 사용하며 세션 상태에 의존하지 않는다. [Supabase 공식 연결 안내](https://supabase.com/docs/guides/database/connecting-to-postgres). 실제 모드 검증은 `npm run storage:test-db`로 별도 임시 스키마에서 수행한다.

동기화는 페이지별 구독 범위의 버전 목록만 받는다. 본문은 변경된 리소스만 받는다. 초기 화면은 이미 받은 자료로 표시하며 후속 동기화를 기다리지 않는다. DB 버전 목록은 한 SQL 왕복으로 조회한다. 접속 기록은 같은 HTTP 요청 안에서 필요할 때만 별도 쓰기로 갱신한다(최대 15초에 한 번). 전역 DB 연결 한도 문제를 연결 수 증가로 해결하지 않는다.

서버리스 요청 간 TCP 소켓은 재사용하지 않는다. 운영 검증에서 새 연결은 정상인데 재사용 연결만 멈추는 상황을 확인했기 때문이다. `withDatabaseRequest`의 AsyncLocalStorage로 각 요청의 연결을 분리하고, 요청 안에서는 동일 연결을 재사용하며 Express의 비동기 작업 완료 후 확실히 닫는다. 로컬/관리 스크립트는 기존 지연 생성 연결을 유지한다. API 진입점이 Express를 호출만 하고 반환하면 안 되며 응답 완료와 연결 종료까지 await한다.

실제 업무 전에 짧은 `SELECT 1`로 연결을 확인한다(업무 버전 조회와 별도 왕복). 실패 시 아직 업무가 시작되지 않은 해당 연결만 교체하고 한 번 다시 확인한다. 업무 쿼리·저장 자체를 이 단계에서 재실행하지 않는다. 중복 저장 방지는 기존 요청 ID 규약이 담당한다. 브라우저 연결 종료를 DB 작업 종료로 취급하지 않으며, 트랜잭션이 실행 중일 때 연결을 교체하지 않는다. 두 번 확인에 실패하면 503으로 반환하고 기기 저널을 유지한다. [Supabase 서버리스 연결 복구 지침](https://supabase.com/kb/troubleshooting/troubleshooting-connect_timeout-or-hanging-queries-in-vercel-serverless-functions-775f92). `/api/storage/health`는 연구 내용·자격증명을 노출하지 않는 연결 진단이다.

## 확장 절차

새 기능은 (1) 안정적인 리소스 키와 필드 스키마 (2) 서버 읽기·필드 비교 저장·이력 (3) CollaborationEngine 또는 동등한 검증된 큐 (4) 페이지 소비자 등록 (5) 저장/실패/충돌/복구 UI를 구현한다. 본문을 배열 전체나 사이트 설정 전체로 덮어쓰지 않는다. 새 데이터 형식은 구버전 요청으로 지워지지 않도록 검증한다.

국제 연표는 사건별 리소스로 저장한다. 최초 서버 시드는 트랜잭션 잠금 아래 한 번만 생성한다. 각 브라우저의 기존 원문은 이관 전에 별도 백업한다. 기본 데이터와 브라우저 편집본의 차이만 서버에 병합하고 충돌은 사용자가 선택한다. 로컬 포트/운영 도메인별 원본은 서로 다르며, 접근하지 못한 브라우저를 이관 완료로 간주하지 않는다. 기존 브라우저 원본과 내보내기는 보존한다.

## 구현 위치와 국제 연표 이관

- `client/src/lib/sync-lifecycle.ts`: 조회 소비자·환경·세대·중복 실행 제어. React 페이지는 `useCollaborationSync(scope, ready)`로 등록한다.
- `client/src/lib/cap-collab-engine.ts`: 필드 비교, IndexedDB 저널, 리소스별 직렬화, 전체 동시 전송 최대 2개, 응답 유실 재시도, 충돌·이력 되돌림. 쓰기와 조회 수명은 독립이다.
- `server/cap-collaboration.ts`: 버전 단일 조회·접속 갱신 제한, 트랜잭션 저장·요청 ID 이력. 기존 `cap_settings`, `cap_edit_operations`, `cap_editors`를 재사용해 운영 DDL이 필요 없다.
- `shared/international-storage.ts`: 사건 필드 스키마. 날짜/기간은 timing, 국가/범위는 position으로 각각 원자적으로 비교한다. 삭제/복원은 사건 전체를 비교해 수정과 경합하면 충돌한다.
- `client/src/lib/use-international-storage.ts`: 읽기·기존 브라우저 이관·사건별 변경 전달. 서버 초기화 전 기본 자료로 먼저 읽기 화면을 표시하고, 서버 확인 후 편집을 연다.

국제 연표 DB 키는 `cap_settings.international_event:<id>`이며 리소스 키는 `intl:<id>`다. `international_seed_v1`은 최초 시드 마커다. 이후 배포의 기본 데이터 변경을 서버 확정본 위에 자동 덮어쓰지 않는다. 후속 자료 추가는 별도의 검토된 DB 이관으로 수행한다.

브라우저 원본 키 `fiscus-international-timeline-v1`은 수정/삭제하지 않는다. DB 전환 직전 원문은 `fiscus-international-timeline-before-db-v1`에 보관한다. 원문 SHA-256별 사건 이관 진행표 `fiscus-international-timeline-db-import-v1`을 기록하므로 재로드 중단 후 이미 저널에 보관한 사건을 중복 이관하지 않는다. 구버전 창이 원문을 다시 바꾼 경우 새 차이 비교가 필요하며 이전 내용을 조용히 덮어쓰지 않는다. 기존 기기 복구 초안과 같은 사건이 있으면 복구를 먼저 요구한다.

`fiscus-international-timeline-db-cache-v1`에는 **서버 확인본과 버전만** 저장한다. 미저장 작성본은 IndexedDB 저널에 둔다. 확인본 캐시가 있는 기기에서는 서버 읽기에 실패해도 해당 버전을 기준으로 초안을 작성할 수 있고, 재접속 시 서버가 다시 비교한다. 캐시·원본이 손상되거나 최초 접속에서 서버 확인이 안 되면 편집을 잠그고 원문을 보존한다.

두 PC의 동기화는 서버를 통해 이뤄진다. 같은 브라우저의 다른 탭도 독립 세션으로 비교한다. 탭 간 한 명 대표 통신 같은 추가 복잡성은 현재 도입하지 않는다.

## 필수 검증·운영

두 클라이언트의 독립/동일 필드 편집, 삭제와 수정 경합, 저장 중 추가 입력, 응답 유실 재시도, 숨김/복귀/페이지 이동/오프라인, 새로고침 초안 복구, 초기 읽기 실패를 검증한다. DB 저장 변경은 임시 스키마의 실제 Postgres 통합 검증을 포함한다. 운영 자료를 테스트 내용으로 수정하지 않는다.

비활성 페이지의 정기 조회는 0회, 활성 페이지는 기존 5초 주기를 유지한다. 별도 presence 호출은 최신 클라이언트에서 0회다. 타이핑/첫 렌더/서버 저장 시간과 요청 수·메모리·CPU를 같은 조건으로 비교한다. 절감률은 측정 전 확정하지 않는다.
