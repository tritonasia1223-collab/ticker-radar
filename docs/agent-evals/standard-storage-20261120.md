# 표준 저장 프로세스 적용 검증

순서: 공통 아키텍처 문서와 문서 색인/작업 가이드 연결 → 경제사·그래프 비교의 조회 생명주기와 통합 동기화 → 국제 연표 사건별 DB 저장·브라우저 이관.

기존 경제사의 칸 확정/인사이트 저장 시점은 보존한다. 최신 클라이언트는 별도 state/presence 타이머를 사용하지 않는다. 구버전 API 경로는 유지하므로 배포 당시 열려 있던 창의 저장은 계속 허용된다.

## 관측 기준

사용자 제공 CSV 1,000개 요청(2026-11-20 06:03:07~06:46:17 UTC): state 656, presence 314, 실제 edit 3, 기타 27. 현재 구간의 97%가 반복 동기화였다. 이 표본을 전체 과거 청구액의 기여도로 환산하지 않는다.

## 검증 결과

- TypeScript, 전체 86개 테스트 파일 / 660개 테스트, 프로덕션 빌드 통과. 기존 Browserslist 노후·대형 World 청크 경고 유지.
- 운영 사전 백업: `script/cap-backup.2026-11-20T07-24-46.json` (Git 제외). flows 158 / nodes 2426 / edges 878 / links 0 / settings 45. DB 구조 변경·기존 연구 자료의 대체 없음.

- 실제 Postgres의 새 임시 스키마에서 기존 협업 통합 검증과 국제 연표 검증 통과. 운영 연구 자료 쓰기 없음, 테스트 스키마는 종료 후 정리.
- 국제 연표 동시 초기화, 독립 필드 병합, 동일 필드/삭제·수정 충돌, 삭제 사건 시드로 재생성 금지, 잘못된 날짜 저장 롤백, 복원, 국제 연표만의 버전 목록, 접속 시각 15초 쓰기 제한 검증.
- 별도 임시 UI DB와 5194 로컬 앱에서 두 창 본문 충돌 → 서버 내용 선택 → 저장 완료 → 새로고침 지속 확인.
- 경제사 칸 타이핑 중 저장 상태 유지, blur 저장, 새로고침 후 작성본 유지 확인.
- 두 창 모두 다른 메뉴로 이동한 전후 통합 sync 누적 호출 58회로 동일. 별도 presence 호출 없음.
- 로컬 원본을 가진 테스트 브라우저에서 본문 차이와 삭제 기록 이관, 삭제 목록 복원 확인. 기존 원본을 덮어쓰는 경로 제거.
- 자동 테스트: 가시성/오프라인/이탈/복귀, 늦은 응답 무효화와 중복 wake 병합, 전체 동시 쓰기 최대 2개, 포커스 수신 보류 중에도 저장 ACK 처리, soft-delete 충돌 선택, 기간·색상·메타데이터 왕복 보존.

## 운영 확인 시 제한

운영 배포 후 국제 연표 DB 읽기와 저장 완료 표시 확인. 테스트 자원 정리 중 기존 세션 풀 15개 한도 오류가 재현되어, Vercel의 확인된 Supabase 공유 풀러 연결만 같은 DB의 6543 트랜잭션 모드로 전환한다. 로컬/관리 연결은 유지한다. 실제 트랜잭션 풀의 동시 초기화·병합·충돌·동일 ID 재시도와 최신 값 보존 검증도 통과했다. 이번 작업에서 만든 UI 테스트 스키마 3개와 트랜잭션 풀 테스트 스키마는 정리 완료.

테스트 통과를 모든 사용자 브라우저의 이관 완료로 간주하지 않는다. 사용자별 기존 편집본은 그 브라우저로 최신 국제 연표에 진입해야 비교 이관된다. 충돌이 있으면 서버/기기 내용을 선택해야 확정된다. 구버전 창은 계속 기존 반복 호출을 하므로 해당 창을 새로고침해야 절감 효과가 적용된다.

활성 페이지는 5초 주기를 유지한다. 호출 감소와 응답시간 개선은 서버 캐시/동시성/네트워크에 따라 달라지며 청구액 감소율을 보장하지 않는다.
