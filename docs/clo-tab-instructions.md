# Ticker Radar — CLO 리스크 모니터 탭 지시문 (v2, 부실 조기경보로 재정의)

> **개정 이력**: v1 은 "ETF 일간 홀딩스로 딜 유니버스·보유변화를 추적"하는 모델이었다.
> 실제 논지가 명확해지면서(아래 §0) v2 로 재정의한다 — 이 탭은 **신용 부실 조기경보 대시보드**다.
> v1 에서 만든 것(딜 유니버스 + CUSIP↔N-PORT 라이브 프리뷰)은 버리지 않고 **부실 지표를 매다는
> 스캐폴드**로 강등·재편한다(§3-D, §4 Phase 5).

## 0. 목적 (재정의)

**논지**: CLO 는 (구조는 서브프라임과 다르지만) 신용 사이클이 꺾일 때 터질 수 있는 위험 자산군이다.
CLO 는 2024년 신규 레버리지드 론의 61%를 매입하고 전체 레버리지드 론 시장의 64%를 보유 —
**CLO 수요가 곧 레버리지드 론 시장의 유동성 그 자체**다. 따라서 이 탭의 목적은:

> **공개 프록시로 CLO/레버리지드 론 신용 스트레스의 온도를 재고, 사이클이 꺾이는 신호를 조기 포착한다.**

즉 "어느 ETF가 뭘 선호하나"(v1)가 아니라 **"담보가 썩고 있나 / 이 신용 사이클이 위험한가"**를 본다.

### 정직한 데이터 한계 (이 탭의 정체성을 규정함)
- **개별 CLO 담보풀의 회사별 연체·부실은 공개 데이터로 실시간으로 볼 수 없다.** 그 원본(트러스티
  리포트·Intex)은 투자자 전용이다. 로그인 스크래핑·유료접근은 **금지**(이용약관 리스크).
- 그러므로 이 탭은 "정밀 CLO 부실 스캐너"가 **아니라** **공개 프록시 삼각측량 기반 조기경보 대시보드**다.
  이 선을 넘어 없는 정밀도를 참칭하는 순간 실패다(규약 "반증 먼저"와 직결).

### Non-goals (구현 금지)
- 스코어링 엔진 없음 — 순수 descriptive. "이거 사라/팔아라" 신호 아님.
- 트러스티 리포트·Intex 등 유료/제한 데이터 접근·평가사 로그인 스크래핑 금지.
- 개별 딜의 회사별 연체율을 "재구성했다"고 표기 금지 — 프록시임을 항상 명시.

## 1. 규약 준수 (CLAUDE.md 스코어링 레버 규약 준용 — v1 과 동일)

1. **반증 테스트가 인프라 구축에 선행.** 자동 수집 후보(BDC non-accrual·LSTA 헤드라인 등)는
   **빌드 전에 프로브로 취득/추출 가능성부터 반증**한다. 게이트 실패 시 보고 후 대기.
2. **커밋 단위 = 1지표(1기능).** 프로브와 구현을 한 커밋에 섞지 않는다.
3. **네거티브 컨트롤.** 파서·조인·추출 검증 시 "맞는 게 붙는가"만이 아니라 "엉뚱한 게 안 붙는가".
4. **공유 Supabase 에 `drizzle-kit push` 절대 금지**(#26). 테이블은 수기 `CREATE TABLE IF NOT EXISTS`.
5. 모든 프로브 스크립트는 `script/` 에 회귀 하네스로 보존(삭제 금지).

브랜치: `feat/clo-monitor` (또는 프로젝트 관행상 master 직접). 이슈 순번 C-* 로 지칭.

## 2. 부실 지표 taxonomy (핵심 재구성)

부실은 **두 층위 + 맥락**으로 나뉜다. 각 지표의 자동화 난이도가 다르므로 반드시 표대로 취급한다.

| 층위 | 지표 | 소스 | 무료 | 자동화 | 무엇을 말해주나 |
|---|---|---|---|---|---|
| **시스템** | HY OAS 스프레드 | FRED `BAMLH0A0HYM2` | ✅ | 🟢 즉시 | 시장의 실시간 신용 스트레스 — 가장 빠른 공개 신호 |
| **시스템** | BDC non-accrual % | EDGAR 10-Q/N-PORT (ARCC·FSK·BXSL·OBDC·GBDC…) | ✅ | 🟡 프로브 | 사모신용 연체의 가장 직접적 공개치, 론시장 선행 온도계 |
| **시스템** | 레버리지드론 디폴트율 | Morningstar LSTA 헤드라인 (언론/LCD) | ✅(헤드라인) | 🟡 프로브/수동 | 시장 전체 액면 디폴트율 |
| **시스템** | LME 포함 확장 디폴트율 | Fitch/Moody's 분기 리서치 | ✅ | 🔴 수동 | LME(가짜 비디폴트) 걷어낸 실제 스트레스 |
| **딜** | CCC 버킷 비중 (한도 통상 7.5%) | ECC·OXLC 분기, 운용사 코멘터리 | ✅ | 🔴 수동 | 담보 부실 선행지표 — 초과분은 할인 평가 |
| **딜** | OC 테스트 쿠션 | ECC 월간 업데이트 | ✅ | 🔴 수동 | 위반 시 에쿼티/주니어 현금흐름 차단 → 담보 건전성 추세 |
| **맥락** | CLO 시장 총규모/발행 | SIFMA 무료 엑셀, BofA 헤드라인(~$1.4T), LCD 발행 | ✅ | 🟡 프로브 | 사이클 성장 속도·위상 |
| **교차검증** | criticized/classified 자산 | Fed 반기 FSR, SNC 리뷰(연1회) | ✅ | 🔴 수동 | 은행 감독 관점 부실(시의성 낮음, 교차검증용) |

자동화 범례: 🟢 즉시(불확실성 없음) / 🟡 프로브 필요(취득·추출 가능성 미검증) / 🔴 수동 입력.

## 3. 데이터 소스 명세

### (A) 시스템 부실 — 자동/프로브
- **FRED**(`https://api.stlouisfed.org/fred/series/observations`, 키 필요): `BAMLH0A0HYM2`(HY OAS) 최소,
  추가 후보(레버리지드론 인접 스프레드·BDC 지수)는 UI 단계에서 결정. **정적 JSON 프리페치**(capitalism
  패턴 준용, 런타임 fetch 0) 또는 소규모 cron.
- **BDC non-accrual**(EDGAR): 대형 BDC(ARCC·FSK·BXSL·OBDC·GBDC·PSEC 등)의 10-Q/10-K·N-PORT 에서
  non-accrual 비율(이자 수취중단 자산/공정가치) 추출. **취득·추출 가능성 프로브 선행**(§4 Phase 0').
  EDGAR 예의: UA 필수(`ticker-radar admin@<이메일>`), ≤10req/s.
- **레버리지드론 디폴트율**(LSTA/Morningstar 헤드라인): 언론/LCD 아웃룩에 인용되는 헤드라인 수치.
  안정 취득 경로 프로브 선행. 실패 시 수동 입력으로 강등.

### (B) 딜 층위 부실 프록시 — 수동 (문서 §7 레이어)
- ECC(Eagle Point)·OXLC(Oxford Lane) 분기·월간 자료의 **자기 포트폴리오 CCC 비중·OC 쿠션·디폴트
  익스포저**를 시장 프록시로. 운용사(Janus/Panagram) 월간 코멘터리의 담보풀 디폴트율·워스트 섹터.
  → 사람이 주/월 1회 수집해 CSV 입력.

### (C) 시장 규모/맥락 — 프로브/수동
- **SIFMA** 미국 구조화금융 통계(분기 엑셀, 무료) — 발행·잔액 시계열. 안정 URL·스키마 프로브.
- **BofA/LCD** 헤드라인(~$1.4T 잔액, 연 발행) — 수동 또는 언론 인용.

### (D) 스캐폴드 (v1 에서 이미 구축 — 부실 신호 아님, 뼈대)
- **ETF 홀딩스 딜 유니버스 + CUSIP↔N-PORT 조인**: `server/clo.ts` + `/clo` 라이브 프리뷰.
  JAAA·JBBB 실증 완료(CUSIP 은 깨끗한 조인키, 생존율 91.8%/97.3%). PAAA·CLOZ 는 URL 확정 대기.
  **이건 "어느 딜에 부실 지표를 매달지"의 뼈대**다. 부실 지표(CCC/OC 등)를 딜에 부착하는 선반으로 재편
  (§4 Phase 5). N-PORT 생존율/신규 배지는 데이터 검증 지표일 뿐 — 부실 대시보드에서는 전면에서 내림.

## 4. Phase 재설계

```
[완료] Phase 0  딜 유니버스/CUSIP 조인 프로브 + 라이브 프리뷰   ← v1, DONE
Phase 0'  부실 자동소스 프로브 (게이트)  ─┐
          · BDC non-accrual 추출 가능성   │→ Gate C·D → Phase 2(자동 트래커)
          · LSTA 헤드라인 취득 가능성     ┘
Phase 1   FRED 거시 스트레스 스트립  (🟢 확실·즉시, 프로브 불요)
Phase 2   BDC non-accrual 트래커  (Phase 0' 통과 시)
Phase 3   수동 부실지표 레이어  (CCC/OC/LME CSV 입력)
Phase 4   시장 규모/맥락  (SIFMA/BofA)
Phase 5   스캐폴드 재편  (딜 유니버스에 부실지표 부착 + 프리뷰 재포지셔닝)
```

### Phase 0' — 부실 자동소스 프로브 (게이트)
- `script/probe-bdc-nonaccrual.ts`: 대형 BDC 5~6곳의 최신 10-Q/N-PORT 에서 non-accrual %를
  추출 시도. **네거티브 컨트롤**: 서로 다른 BDC 수치가 뒤섞이지 않는지, 정상영업 자산을 non-accrual 로
  오분류하지 않는지. **Gate C**: ≥4곳에서 안정 추출 성공 → Phase 2 진행. 실패 시 수동 강등 보고.
- `script/probe-lsta-default.ts`: LSTA/Morningstar 헤드라인 디폴트율의 안정 취득 경로 탐색.
  curl 로 안 잡히면 URL 후보 보고 후 수동 입력 경로로.

### Phase 1 — FRED 거시 스트레스 스트립 (앵커)
- `server/adapters/fred.ts` 또는 정적 프리페치. HY OAS 시계열 미니차트가 대시보드 최상단 "사이클
  온도계". 프로브 불요(FRED 는 안정 공개 API). 키는 GitHub Secrets `FRED_API_KEY`(사용자 발급).

### UI 원칙 (재정의)
- **부실 대시보드가 리드**: (1) 거시 스트레스 스트립(HY OAS) (2) BDC non-accrual 추세 (3) 시장 디폴트율
  헤드라인 (4) 딜 프록시(CCC/OC) 카드.
- **딜 유니버스(v1 프리뷰)는 보조 탭/섹션**으로 내리고, 각 딜에 수동 부실지표를 부착하는 뷰로 재편.
- 디자인은 기존 탭 관행 준용. 새 디자인 시스템 금지.

## 5. DB / 저장 (규약 동일)
- **게이트 전 테이블 생성 금지.** Phase 1(FRED)·Phase 2(BDC)가 시계열 저장을 요구하면, 그때 수기
  `CREATE TABLE IF NOT EXISTS`(`clo_*` 프리픽스) 로만. **공유 Supabase 에 `drizzle-kit push` 절대 금지**(#26).
- 원시 파싱 실패 행 비파괴 → `clo_ingest_errors`.
- 현재 `/clo` 프리뷰는 DB 무접촉(요청시 조인). 시계열이 필요해지는 순간이 첫 테이블 시점.

## 6. 사용자(트리톤) 액션 아이템
1. FRED API 키 발급(fred.stlouisfed.org, 무료) → Secrets `FRED_API_KEY`.
2. EDGAR UA 연락 이메일 지정.
3. Phase 0' 프로브가 BDC 필링 URL/포맷 브라우저 확인을 요청하면 협조.
4. 수동 부실지표(CCC/OC/LME) 1차 시드 값 확보(ECC/OXLC 분기 자료).
5. PAAA·CLOZ 홀딩스 URL(DevTools) — 스캐폴드 4종 확장용(우선순위 낮음).

## 7. 수동 입력 레이어 (딜 부실지표)
- CSV 업로드 스크립트로 시작: `script/import-clo-metrics.ts <file.csv>`
  (컬럼: deal_name, as_of, metric[ccc_pct|oc_cushion_pct|default_pct], value, source, source_url).
- deal_name 은 스캐폴드(clo_deals)와 **정확 일치로만** 조인, 미일치는 에러 목록(퍼지매칭 금지 — 오염 방지).
- UI 입력 폼은 CSV 워크플로가 월 2회+ 실사용된 뒤 별도 이슈로.

## 8. 진행 순서 요약
```
[DONE] 딜 유니버스/CUSIP 프리뷰
Phase 0' 부실 자동소스 프로브 ──→ Gate C·D
Phase 1 FRED 스트레스 스트립(즉시) → Phase 2 BDC non-accrual → Phase 3 수동 CCC/OC/LME
                                    → Phase 4 시장규모 → Phase 5 스캐폴드 재편
```
각 이슈 완료 시 커밋에 게이트 통과 근거(측정 수치) 명시. 게이트 보고 전 테이블 생성 금지.
