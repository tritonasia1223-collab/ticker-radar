# 월간 데이터 갱신 운영

일정: **매월 3일 09:00 Asia/Seoul**. [.github/workflows/monthly-data.yml](../.github/workflows/monthly-data.yml)의 GitHub Actions가 서버에서 실행한다. PC·브라우저·Codex 앱은 필요 없다. 첫 정기 실행 예정은 2026-10-03이며 `workflow_dispatch`로 즉시 실행할 수도 있다. GitHub 사정에 따라 시작이 지연될 수 있다.

경제사와 전력시장 경계는 검증 후 자동 반영한다. 세계 현황판의 건설·계약·새 데이터셋은 **검토 후보 수집**까지 자동화하며 사실 판단을 자동 확정하지 않는다. 별도 AI API·유료 수집 키는 쓰지 않는다. 기존 Codex 예약 `fiscus`는 서버 전환 후 중지한다. 미국 유동성·거래 수집 일정은 그대로다.

## 실행 순서

1. `master`의 최신 커밋을 새 Linux 실행 환경에 체크아웃하고 `npm ci`로 잠금 파일에 맞춰 설치한다. 같은 월간 작업은 동시에 실행하지 않는다.
2. `npm run cap:series -- --repair-last-month`로 19종을 수집한다. 실패가 하나라도 있으면 이번 경제사 변경 전체를 원복한다. 실행 전 백업·보고서는 아티팩트로 90일 보관한다.
3. `npm run world:refresh`로 등록된 공식 출처 목록의 새 링크를 수집하고 RTO 경계를 재생성한다. 7개 고유 권역·좌표·닫힌 링·이전 대비 면적 변화 25% 이내를 검증하며 실패하면 원래 지도 파일을 복원한다.
4. [검토 목록](data-refresh/world-latest.md)과 `.github/data/world-source-state.json`에 새 링크·미검토 후보·조회 실패를 기록한다. 기존 후보는 사람이 검토 완료 처리하기 전까지 유지한다. 첫 수집은 기존 기사도 포함한 기준 목록이며, 실제 신규 발표라는 뜻은 아니다.
5. 공개 목록이 자동 접근을 막거나 브라우저 실행을 요구하는 출처는 명시적으로 수동 확인 목록에 둔다. 현재 Micron·TSMC·Lloyd’s List·UNCTAD·Constellation이 해당한다. 자동 출처의 새 오류는 작업 실패로 표시하고 이전 목록을 보존한다. 등록 목록은 `script/world-refresh-sources.json`에서 관리한다.
6. 타입 검사·테스트·빌드 통과 후 경제사 JSON, RTO JSON, 검토 목록·상태, 배포 확인용 `client/public/data-refresh.json`만 봇 커밋한다. 일반 푸시가 다른 편집자의 선행 커밋 때문에 거절되면 실패로 종료한다. 강제 푸시나 무검증 병합은 하지 않는다.
7. Vercel의 해당 커밋 성공 상태와 운영 배포 표식·실제 거시지표 에셋의 해시까지 확인한다. 최대 약 8분 기다리며 실패·다른 배포로 대체됨·불일치는 성공 처리하지 않는다. 원천 실패가 있어 보고서만 게시한 경우에도 최종 작업은 실패로 표시한다.

## 결과 확인과 수동 검토

[GitHub Actions 실행 목록](https://github.com/tritonasia1223-collab/ticker-radar/actions/workflows/monthly-data.yml)에서 실행 요약·보고서 아티팩트를 볼 수 있다. 실패 알림은 GitHub 계정의 Actions 알림 설정을 따른다. 별도 이메일·메신저는 발송하지 않는다. 정기 보고서에는 정상 실행 기록도 남긴다.

검토자는 후보 원문을 읽고 확인된 변경만 해당 World JSON에 반영한다. 개별 자료의 검토일·발표일·출처를 구분하고 전체 `as_of`를 일괄 올리지 않는다. 완료한 후보는 상태 파일의 `pending`에서만 제거하고 `seen`은 유지한다. 그 뒤 `npm run world:refresh`를 실행하면 보고서가 다시 생성된다. 이 명령은 출처를 다시 조회하고 RTO도 검증하므로 변경 내역을 확인한 뒤 커밋한다.

목록 페이지에서 빠진 과거 기사, 같은 URL의 본문 수정, 미등록 출처, 전체 웹 검색까지 감시하지는 않는다. NRC 공지는 해당 연도의 목록을 확인하며, GED 새 버전은 변환·수작업 보강 검토 전까지 기존 지도에 자동 적용하지 않는다.

## 경제사 보존 정책

- 과거 빈티지와 수작업으로 보강한 역사는 보존하며 마지막 저장 날짜 이후의 관측값을 추가한다.
- 나스닥 일별 자료는 **끝난 달의 마지막 유효 관측값**만 월간 표본으로 저장한다. 진행 중인 달은 제외한다. 월간 표본 날짜는 기존 형식에 맞춰 해당 월 1일이다.
- `--repair-last-month`는 나스닥의 가장 최근 저장 월 1개만 원천의 완료된 월말 표본과 대조해 교정한다. 이전 수집기가 월중 값을 고정해 둔 경우를 복구하기 위한 옵션이다. 더 오래된 값은 바꾸지 않는다.
- CPI 전년 대비는 행 수가 아니라 실제 전년도 같은 달과 비교한다. FRED의 원래 월간·분기·주간·일간 시리즈 주기는 유지한다.
- 과거 개정치를 일괄 반영하거나 단종·지표 정의 변경으로 원천을 바꾸려면 먼저 기존 시계열과 연결 방법을 검증한다.

`nuclear:build`, `conflicts:build`, `tx:build`는 자동 실행하지 않는다. 하드코딩된 상태·기준일이나 수작업 보강을 덮을 수 있으므로 위 표는 후보 검토 시 참고하는 자료원이다. 전력시장 경계만 보호 검증을 거쳐 정기 재생성한다. 개인 경제사 사건·메모·협업 DB에는 쓰지 않는다.

필요 권한: 워크플로의 `GITHUB_TOKEN`에 `contents: write`, `statuses: read`. 기존 Vercel Git 연동으로 봇 커밋 배포를 수행한다. 저장소를 private으로 바꾸거나 Vercel 접근 정책을 바꾸면 봇 배포 권한을 다시 확인해야 한다.
