# 월간 데이터 갱신 운영

일정: **매월 3일 09:00 Asia/Seoul**. Codex 앱의 `FISCUS 월간 데이터 갱신` 예약(`fiscus`)이 이 작업에 연결되어 실행된다. 첫 정기 실행 예정은 2026-10-03이다. 2026-09-09에는 초기 갱신을 실행했다.

로컬 실행이므로 컴퓨터와 Codex 앱이 켜져 있어야 하며 프로젝트·네트워크·GitHub 인증이 필요하다. GitHub Actions의 미국 유동성·거래 수집 일정과는 별개다. 예약 설정은 Codex 앱에서 관리하며 저장소를 복제한다고 함께 설치되지 않는다. 실행 시점의 권한 제한 때문에 수집·푸시가 차단되면 실패 원인과 필요한 조치를 보고한다.

## 실행 순서

1. `CLAUDE.md`, [갱신 목록](DATA-UPDATES.md), 직전 `docs/data-refresh/` 기록과 `git status`를 읽는다. 다른 편집자의 변경을 덮거나 포함해 커밋하지 않는다. 원격 최신 상태를 확인하고 안전하게 반영한 뒤 작업한다.
2. 프로젝트 루트에서 `npm.cmd run cap:series -- --repair-last-month`를 실행한다. `script/cap-export/`에 실행 전 JSON 백업과 `capitalism-refresh-latest.json` 보고서가 저장된다(커밋 제외).
3. 19개 시리즈의 성공 여부·최신 관측일·신규 개수·교정 내역을 확인한다. 원천 발표 지연과 수집 오류를 구분한다. 오류나 겹침 검증 실패는 종료 코드 1이며 일부 성공을 전체 성공으로 처리하지 않는다.
4. 세계 현황판의 아래 범위를 공식 발표·규제기관·데이터 제공기관과 대조한다. 새 근거가 있는 항목만 수정하고 조회 실패·미확인 범위를 기록한다. 검색 결과 요약만으로 가동·금액·용량을 확정하지 말고 원문을 확인한다.
5. `docs/data-refresh/YYYY-MM-DD.md`에 변경 전후, 자료 발표일, 검토일, 출처 URL, 유지·보류 이유를 기록한다. 바뀌지 않은 데이터의 `as_of`를 갱신일로 올리지 않는다. 파일 전체를 재검토하지 않았다면 개별 항목의 `reviewed_at`과 기록으로 범위를 한정한다.
6. 변경이 있으면 `npm.cmd run check`, `npm.cmd test`, `npm.cmd run build`를 실행한다. 데이터의 ID 중복·참조 관계·날짜 순서·숫자 단위와 과거 데이터 보존도 점검한다.
7. 이 작업의 파일만 명시해 커밋하고 `master`에 일반 푸시한다. 사용자는 이 범위의 데이터 갱신·검증·배포를 승인했다. 강제 푸시는 하지 않는다. 해당 커밋의 Vercel 성공 상태와 운영 정적 에셋을 확인한다.

## 경제사 보존 정책

- 과거 빈티지와 수작업으로 보강한 역사는 보존하며 마지막 저장 날짜 이후의 관측값을 추가한다.
- 나스닥 일별 자료는 **끝난 달의 마지막 유효 관측값**만 월간 표본으로 저장한다. 진행 중인 달은 제외한다. 월간 표본 날짜는 기존 형식에 맞춰 해당 월 1일이다.
- `--repair-last-month`는 나스닥의 가장 최근 저장 월 1개만 원천의 완료된 월말 표본과 대조해 교정한다. 이전 수집기가 월중 값을 고정해 둔 경우를 복구하기 위한 옵션이다. 더 오래된 값은 바꾸지 않는다.
- CPI 전년 대비는 행 수가 아니라 실제 전년도 같은 달과 비교한다. FRED의 원래 월간·분기·주간·일간 시리즈 주기는 유지한다.
- 과거 개정치를 일괄 반영하거나 단종·지표 정의 변경으로 원천을 바꾸려면 먼저 기존 시계열과 연결 방법을 검증한다.

`nuclear:build`, `conflicts:build`, `tx:build` 등을 무조건 재실행하지 않는다. 하드코딩된 상태·기준일이나 수작업 보강을 덮을 수 있으므로 새 버전과 차이를 먼저 확인한다. 개인 경제사 사건·메모·협업 DB에는 이 작업으로 쓰지 않는다.

실제 데이터 변경·배포 완료, 실패 또는 사용자 조치가 필요한 경우 알린다. 변화가 없는 확인에는 반복 알림을 보내지 않는다.
