# 미국 유동성 주간 해설 편집 인수인계

작성일 2026년 10월 19일 · 사례 범위 9월 5주차를 기준으로 작성한 10월 1주차와 2주차 · 적용 대상 미국 유동성 B안의 주간 해설

사용자가 원하는 해설은 전주에 세운 판단을 이번 주 데이터로 갱신하는 글이다. 그래프의 숫자를 모두 읽어주거나, 매주 처음부터 시장을 설명하는 글이 아니다. 이번 주 달라진 점을 먼저 말하고, 그 변화가 다른 지표와 어떤 관계인지 설명한다. 그대로인 내용은 필요한 만큼만 유지한다.

초안은 적극적으로 작성한다. 사용자는 “너무 지나치면 내가 거둬내는 게 편함. 아예 처음부터 없는 것보다는”이라고 요청했다. 다만 최종 문안에서는 중복 수치, 반복 정의, 형식적인 주의 문장과 다음 주 예고를 걷어냈다. **분석을 충분히 한 뒤 필요한 해석을 골라 쓰는 것**이 목표다. 처음부터 해석을 생략하거나 모든 문단을 무조건 짧게 만드는 것으로 학습하지 않는다.

**핵심 변화의 원인은 내부 데이터셋 안에서만 찾지 않는다.** 지난주와 다른 중요한 움직임이 있으면 외부 자료를 적극적으로 조사한다. 또한 정확성은 수치를 전부 나열하거나 용어를 압축하는 것으로 확보하지 않는다. 사람이 한 번 읽고 무엇이 왜 달라졌는지 이해할 수 있는 문장으로 쓴다. 두 항목은 2026년 10월 19일 사용자가 명시적으로 추가한 원칙이다.

## 적용 범위와 근거 구분

### 반복 운영과 최신화

2026-10-19 사용자 요청에 따라 **데이터 갱신 → 이 문서 읽기 → 전주 비교와 외부 조사 → 해설 초안·로컬 미리보기 → 사용자 직접 피드백 → 수정본과 이 문서 갱신 → 다음 주 작성**을 반복한다. 실행 방법과 기록 형식은 [주간 해설 운영 절차](../tools/liquidity-editorial/README.md)에 있다.

사용자가 평소처럼 수정·삭제·추가를 요청하면 별도의 “학습해줘” 지시 없이 기록을 최신화한다. 원본 초안은 보존하며 피드백 원문, 수정 전후, 이유, 적용 범위를 함께 남긴다. 주차별 편집은 해당 주차에, 재사용할 공통 원칙은 이 문서의 관련 본문에 통합한다. 같은 규칙을 반복 추가하지 않고 바뀐 지시는 이전 범위와 변경 이력을 남긴다.

**자동 작성한 초안 자체와 사용자 무응답은 학습 근거가 아니다.** 직접 받은 사용자 피드백만 학습 기록의 출발점으로 삼는다. 추론한 선호는 추론으로 표시하며, 문안을 채택한 사실과 경제적 사실 검증을 구분한다. 단순 오타 수정에 공통 원칙을 발명하지 않는다. 제안을 요청했을 뿐인 문장은 승인된 편집으로 저장하지 않는다.

정기 작성은 금요일 11:00(한국시간), 미완료 재확인은 토요일 11:00이다. 기존 주차를 중복 작성하거나 수정본을 덮어쓰지 않고 로컬 미리보기까지만 진행한다. 예약은 데이터 수집 완료를 검사하는 방식이며, 배포는 별도의 명시 요청이 필요하다. 운영 기록 원본은 `C:\ticker-radar-master`에 유지한다.

2026-10-23 운영 보완: 예약 시간만으로 수집 완료를 추정하지 않는다. 사용자 요청 “원인 파악하고 해결”에 따라 11시 작성 전 실제 API 기준일과 GitHub 실행 결과를 확인하고, 미수집이면 기존 수집을 직접 실행하는 복구 단계를 연결했다. 자동 생성 초안에서 추론한 편집 선호가 아니라 수집 운영 정정이다. 자세한 절차는 운영 문서, 조사 근거는 [수집 지연 복구 기록](LIQUIDITY-COLLECTION-RECOVERY-20261023.md)을 참고한다.

이 문서의 시장 문장은 **당시 편집 사례**다. 사용자가 문구를 채택했다는 사실은 그 경제적 설명이 모든 시점에 유효하거나 사실 검증이 끝났다는 뜻이 아니다. 다음 주 수치와 원인 설명은 새 자료로 확인한다. 특히 과거 문구의 “위험권”, “경고 기준”, 등급 대응, RMP의 영향, 언론 집계는 영구 판정 규칙으로 옮기지 않는다.

1주차는 챕터별 공동 작성이어서 사용자 수정 전의 단일 전체 초안이 없다. 2주차는 AI가 한 번에 채운 최초 초안과 사용자의 수정 결과를 비교할 수 있다. 아래에서 사용자 제공 정보, AI 제안, 실제 반영 결과를 구분한다. 삭제 이유를 사용자가 직접 설명하지 않은 경우에는 편집상의 추론으로만 다룬다.

## 다음 작업자가 먼저 적용할 원칙

1. 전주 최종 해설을 먼저 읽는다. 각 문단의 판단과 남겨둔 질문을 이번 주에 어떻게 갱신할지 확인한다.
2. 데이터 비교는 넓게 한다. “거의 수치가 비슷한 것 빼고 나머지”를 요청받으면 AI가 중요도만으로 항목을 누락하지 않는다. 비교 목록과 페이지에 실을 해설은 별개다.
3. 왼쪽은 해당 기간의 해석, 오른쪽은 그래프와 읽는 방법이다. 정의를 매주 해설에 반복하지 않는다.
4. 첫 문장은 이번 주 변화 또는 판단이다. 다음 문장은 이유나 다른 지표와의 관계다. 옆에 보이는 숫자는 판단에 필요한 것만 다시 쓴다.
5. 주간 변화, 4주 변화, 13주 변화, 관측 수준을 구분한다. 서로 반대 방향일 때는 오류처럼 숨기지 말고 기간 차이로 설명한다.
6. “새 관측 없음”과 “새 관측에서도 변화가 작음”을 구분한다. 유지할 해설이 있으면 블록 아래 작은 빨간 글씨로 새 관측이 없음을 표시한다.
7. 사용자가 삭제한 해설은 같은 주차에서 자동 복구하지 않는다. 그래프·정의까지 삭제한 것으로 확대 해석하지 않는다.
8. 사용자 문안을 바꿀 때는 지정한 범위만 고친다. 명확한 오타와 단위 표기는 바로잡되, 주장이나 의미를 바꿔야 하면 바뀐 문장을 보여준다. 이미 승인한 수정은 다시 묻지 않는다.
9. 과거 평균·중앙값·관측 고점과 비교한다. 자체 임계값이나 시나리오에 억지로 끼워 맞추지 않는다. 과거 고점을 넘었다는 관측과 위험 판정은 다르다.
10. 기본 작업은 로컬 미리보기다. 배포 요청이 있을 때 해당 범위를 배포한다. 이전 배포 승인을 이후 모든 편집의 상시 배포 권한으로 취급하지 않는다.
11. 전주 대비 핵심 변화가 있으면 외부 조사를 작성 과정에 포함한다. 내부 데이터가 보여주는 동시 움직임만으로 원인을 확정하지 않는다. 조사 요청을 사용자가 따로 할 때까지 기다리지 않는다.
12. 독자가 이해하기 쉬운지를 정확성과 함께 검토한다. 근거 수치 전체는 조사 기록에 남기고, 본문에는 해석을 이해하는 데 필요한 수치를 고른다. 단어를 줄여 짧아진 문장과 이해하기 쉬운 문장은 다르다.

## 실제 전후 문장에서 배울 점

### 숫자를 더 넣는 것보다 비교의 의미를 남긴다

초안 03의 일부:

> 최근 4주간 늘어난 순유동성 약 1,120억 달러 가운데 약 1,093억 달러가 지급준비금 증가로 나타났습니다. 이번 회복은 은행이 연준에 보유한 잔액 쪽에 대부분 반영됐습니다. 다만 준비금 증가가 곧바로 기업 대출 증가를 뜻하는 것은 아닙니다.

사용자 수정 후 반영문:

> 지급준비금도 순유동성과 거의 같은 방향입니다. 최근 한 달은 크게 늘었지만, 분기로 보면 감소 추세입니다. 이는 9월 말보다는 여유가 생겼다는 판단과, 분기 전체로 충분히 회복했는지는 더 봐야 한다는 판단을 동시에 할 수 있습니다.

남은 가치는 두 기간의 관계다. 숫자 자체는 그래프에 있으므로 문장에서 모두 반복할 필요가 없었다. 그렇다고 모든 수치를 빼지는 않는다. 비교를 성립시키는 금액·격차·비중은 다른 항목에서 계속 사용했다.

### 새로운 관심점은 구체적인 방향 변화에서 나온다

초안 04의 끝:

> 시장이 이번 주 새로 소화한 물량은 단기채 쪽에 몰렸습니다.

사용자 수정 후 반영문:

> 최근 4주로 보면 여전히 중장기채가 순증가의 대부분을 차지하지만, 앞으로 단기채 쪽으로 다시 흐름이 바뀔지 주목됩니다.

사용자가 추가한 것은 막연한 “계속 확인”이 아니라, 앞서 설명한 만기 구성의 변화가 이어질지라는 질문이다. 다음 주에는 그 질문에 먼저 답한다.

### 주의 문장은 필요에 따라 남긴다

입찰에서는 다음 문장을 남겼다.

> 단, 9월 장기물 입찰이 빠지고 10월 8일 입찰분이 들어왔기 때문에, 동일한 채권의 수요가 그만큼 강해졌다는 뜻은 아닙니다.

반면 할인창구에서는 일별 내역이 없어 증가 시점을 확정할 수 없다는 긴 설명을 최종 문안에서 덜어냈다. 사용자가 불확실성을 전부 싫어한다고 해석하지 않는다. **주장을 바꾸는 조건은 한 번 남기고, 삭제한 근거에 기대던 주장도 함께 좁힌다.** 설명을 지웠다고 확정성이 강해져서는 안 된다.

### 차이가 갈리는 곳을 첫 문장으로 올린다

1주차 사용자 수정 후 첫 문장:

> 이번 주 회사채 금리는 IG(-4bp)와 HY(-8bp)는 소폭 내려갔지만, CCC만 꽤 크게(+40bp) 올랐습니다.

2주차 사용자 수정 후 첫 문장:

> 지난주 CCC 등급만 금리가 오른 것 대비, 이번 주에는 HY까지 함께 올랐습니다. IG 금리는 이번에도 2bp 하락했습니다.

두 번째 주의 글은 첫 번째 주 판단을 갱신한다. IG·HY·CCC 정의를 다시 설명하는 대신, 악화가 CCC에만 머무는지 HY에도 번지는지를 말한다. 다만 가격 변동만으로 자금 유출이나 부실 발생을 단정하지 않는다.

### 표현 수정과 수치 정정을 구분한다

사용자 CP 요청은 “이번 주 21bp로 지난주와 같은 수준”이었다. 30일물 자료 대조 결과 지난주 수요일은 22bp여서, 최종 반영문은 다음과 같다.

> 30일물 기준 A2/P2와 AA의 금리차는 10월 14일 21bp로, 지난주 수요일의 22bp와 비슷한 수준입니다.

21bp라는 현재값과 “큰 변화 없음”이라는 취지는 유지하되, “같다”를 “비슷하다”로 바꿨다. 이 변경은 사용자 문체 선호가 아니라 데이터 확인에 따른 정정이다. 향후 편집 기록에도 작성 주체와 정정 사유를 남긴다.

## 문체와 구성의 기본값

### 사람이 읽는 문장으로 쓴다

이 항목은 2026년 10월 19일의 명시 지시다. 문장을 정확하게 만들려고 숫자와 기술 용어를 과하게 넣으면 오히려 독자가 비교 기준과 핵심 관계를 놓친다. 먼저 무엇이 달라졌는지 쉬운 말로 쓰고, 그 판단에 필요한 숫자를 뒤에 붙인다.

- “누가 무엇을 했고, 무엇이 달라졌는가”가 드러나게 쓴다. 원인을 확인하지 못했으면 관측된 관계까지만 설명한다.
- 모든 현재값·이전값·증감액을 한 문장에 넣지 않는다. 수치 하나를 뺐을 때 판단이 달라지거나 크기를 오해할 때만 남긴다. 나머지는 그래프나 조사 기록에서 확인할 수 있게 한다.
- “4주 순증 반전”, “창 이탈”, “분기 지준 축소”처럼 명사를 압축해 쌓지 않는다. “최근 4주 합계가 감소에서 증가로 바뀌었습니다”, “비교 기간에서 해당 주가 빠졌습니다”처럼 문장으로 푼다.
- TGA·SOFR·OAS처럼 페이지에서 이미 정한 지표 이름은 유지한다. 대신 주변 설명을 쉽게 쓴다. 이미 정의한 약어를 매 문단 다시 풀어 쓰거나 TGA를 다시 긴 명칭으로 바꾸지는 않는다.
- 설명의 방향이 바뀌면 문단을 나눈다. 긴 괄호 안에 원인·수치·한계를 모두 넣지 않는다. 사용자가 특정 문장의 괄호 처리를 지정하면 그 범위를 따른다.
- 문장을 짧게 만들기 위해 비교 기간, 단위, 주어를 지우지 않는다. 38bp가 현재 수준인지 증가 폭인지 독자가 추측하게 하지 않는다.

다음은 원문 인용이 아닌 작성 방식 예시다.

| 읽기 어려운 표현 | 풀어 쓴 표현 |
|---|---|
| 창 이동에 따른 단기채 순상환분 이탈로 4주 순증 반전 | 최근 4주 합계가 증가로 바뀐 데에는 비교 기간이 한 주 이동한 영향도 있습니다. 단기채를 많이 상환했던 주가 이번 계산에서 빠졌기 때문입니다. |
| CCC OAS 38bp 확대, HY 대비 격차 9.51%p | CCC 기업에 요구하는 위험 프리미엄이 이번 주 38bp 더 높아졌습니다. HY 전체와의 격차도 벌어져, 낮은 신용등급에 부담이 더 집중되는 모습입니다. |

두 번째 예시에서 격차의 정확한 크기가 판단에 필요하면 9.51%p를 추가한다. 숫자 수를 정해놓고 기계적으로 빼는 규칙은 아니다.

### 명시적으로 확인된 선호

- 그래프별 해설을 그 그래프 옆에 배치한다. 05 이후 긴 종합 해설을 챕터 맨 위에 몰아두지 않는다.
- 오른쪽 지표 정의·읽는 방법은 회녹색 블록, 왼쪽 기간별 해설은 채도를 낮춘 노란 블록으로 구분한다.
- 해설은 해당 위치에 놓고 스크롤을 따라오지 않는다. 예외는 주차 이동용 상단 헤더다. 헤더는 스티키이며 주차를 바꿔도 비교하던 위치를 유지한다.
- 강조는 지정한 문장이나 핵심 구절에 한정한다. 25bp 인상 블록은 첫 문장만 볼드, 나머지는 일반 글씨다.
- 별도 블록과 줄바꿈도 편집 의도다. 내용을 합치거나 문장 전체를 임의로 다시 쓰지 않는다.
- 새 관측 없음은 블록 아래 작고 빨간 글씨로 쓴다. 해설을 삭제했으면 그 해설의 안내만 덩그러니 남기지 않는다.
- 고정 구성 항목은 주차마다 규모 순으로 재정렬하지 않는다. 할인창구·레포·달러스왑 등의 순서를 유지한다.

### 편집에서 추론한 기본값

- 한 블록은 보통 1~2문단에서 시작한다. 설명 가치가 있으면 길게 써도 된다. 고정 글자 수 제한은 없다.
- 첫 문장은 “이번 주 무엇이 달라졌나”, 다음은 “그래서 어떻게 읽나”다. 매번 이 문형을 기계적으로 반복하지 않는다.
- 숫자는 변화의 크기나 해석을 떠받치는 것만 고른다. 방향·격차·구성비가 더 유용하면 현재값 나열을 생략한다.
- “이는 …라는 뜻입니다”처럼 독자가 의미를 바로 이해할 수 있는 연결을 선호한다. 연결의 타당성은 별도로 검증한다.
- “함께 보겠습니다”, “다음 주 확인해야 합니다”, “단정할 수 없습니다”를 매 단락 끝에 자동으로 붙이지 않는다.
- 관련 지표는 연결하되 모든 챕터를 하나의 거대한 결론으로 묶으려 하지 않는다. 서로 다른 방향인 이유도 해설이 될 수 있다.

BDC의 P/NAV는 시장 평가, 부실·PIK는 분기 장부다. NAV 분기가 같다면 주가 쪽 변화와 새 공시의 변화를 구분한다. PIK의 분모와 산식을 확인하고 “모두 부실 직전”이라는 과거 문구를 일반 사실로 재사용하지 않는다.

## 다음 주 초안을 쓰는 순서

1. **기준 확보.** 전주 최종 문안, 이번 주 관측, 이전 비교일, 공표 주기, 현재 그래프의 만기·가격 정의를 확인한다. 기존 문서와 수치가 다르면 사후 수정치나 집계 변경인지 구분한다.
2. **변화 목록 작성.** 실제 새 관측 / 같은 관측 / 롤링 창 효과 / 구성 교체 / 수집 결측으로 나눈다. 의미가 작아 보인다는 이유만으로 비교 목록에서 먼저 삭제하지 않는다.
3. **외부 조사와 전주 질문 갱신.** 핵심 변화가 있으면 아래 조사 절차로 배경을 찾는다. 예: 레포는 되돌아왔는가, 할인창구는 줄었는가, CCC만 악화했는가, BDC는 함께 움직이는가. 당시에 없던 새 특징도 추가한다. 데이터만으로 확인한 사실과 조사로 확인한 원인을 구분한다.
4. **해설 배치 결정.** 이번 주 갱신 / 기존 문안 유지와 작은 안내 / 이번 주 생략으로 분류한다. 같은 내용이 개요와 01, 03과 05에 반복되는지 확인한다.
5. **초안 작성.** 근거가 있는 해석은 적극적으로 제안한다. 먼저 변화와 의미를 쓰고, 독자가 판단을 바꿀 조건만 붙인다. 가격 관측에서 자금난·자금 유출·확정된 원인으로 건너뛰지 않는다.
6. **사용자 편집 반영.** 공동 작성 요청이면 챕터별 확정 후 이동한다. 전체 자율 작성 요청이면 전부 채워 미리보기를 제공한다. 확정한 문구를 매번 재승인받지 않는다.
7. **정확성과 가독성 검토.** 수치·부호·기준일·단위·각 해설의 위치를 확인한다. 이어서 처음 읽는 사람이 주어, 비교 대상, 원인과 해석을 이해할 수 있는지 읽어본다. 숫자 나열과 과도한 약칭을 풀어 쓰고, 원본·최종·변경 이유를 보존해 아래 학습 기록을 갱신한다.
8. **배포 범위 확인.** 요청된 경우에만 배포한다. 문서 정리만 한 작업은 배포나 과거 해설 재작성을 뜻하지 않는다.

## 핵심 변화에 대한 외부 조사

내부 데이터는 어떤 항목이 얼마나 바뀌었는지 확인하는 출발점이다. 정책 집행, 세금 납부와 재정 지출 일정, 발행 계획, 개별 기업 사건처럼 움직임을 설명할 배경까지 모두 담고 있지는 않다. 원인이 데이터셋 밖에 있을 수 있다는 전제에서 조사한다.

방향 전환, 반복되는 악화, 평소와 다른 변동, 지표 사이의 엇갈림, 전주에 남긴 질문에 대한 새로운 결과가 조사 계기가 된다. 임의의 몇 bp·몇 %를 넘었을 때만 조사하는 고정 경계선을 만들지 않는다. 사용자가 전체 변화를 요청했으면 중요도와 무관하게 비교 목록은 먼저 보존한다.

1. **설명할 질문을 좁힌다.** 예를 들어 “순유동성이 왜 늘었나”에서 내부 기여도를 확인한 뒤 “TGA가 왜 이번 주에 크게 줄었나”를 조사한다. 관측과 관계없는 일반 시장 전망을 덧붙이지 않는다.
2. **날짜가 맞는 원자료를 확인한다.** 재무부 일일 수입·지출, 입찰 결과, 연준의 정책·운영 일정, 해당 기업의 공시 등 사건과 직접 연결된 자료를 우선한다. 필요한 경우 신뢰할 만한 보도·시장 해설로 추가 배경과 다른 설명을 찾고, 원자료가 뒷받침하는 범위를 구분한다.
3. **다른 원인도 확인한다.** 월초 지급·세수·국채 조달 가운데 무엇이 얼마나 설명하는지, 분기말 일시 수요인지 지속 수요인지 살핀다. 서로 동시에 움직였다는 이유만으로 인과관계로 쓰지 않는다.
4. **사건일과 공개일을 남긴다.** 해당 주간에 실제 일어난 사건인지, 뒤에 발표된 자료로 설명하는지 구분한다. 과거 주차 해설에 미래 사건을 당시 원인처럼 넣지 않는다. 사후 수정 자료를 썼다면 조사 기록에 표시한다.
5. **결론의 강도를 맞춘다.** 공식 자료로 확인된 원인, 여러 자료에 근거한 해석, 아직 확인되지 않은 가설을 구분한다. 원인을 찾지 못하면 유력해 보이는 이야기를 확정형으로 채워 넣지 않는다.
6. **조사와 본문을 분리한다.** 출처 URL, 자료 제목, 공개일, 관측 기간, 핵심 수치와 해석 근거를 기록한다. 페이지에는 독자가 이해하는 데 필요한 결론과 근거만 남긴다. 조사 인용을 추가할 때 기존 요청으로 제거한 그래프별 원자료 하이퍼링크 UI를 자동 복원하지 않는다.

1주차의 TGA 사례가 기준이다. 사용자가 외부 조사로 제공했던 월초 지급 일정과 국채 조달 배경을, 다음에는 AI가 먼저 찾아야 한다. “TGA가 줄어서 유동성이 늘었다”는 회계 관계에서 멈추지 않고 “왜 TGA가 줄었는지”까지 확인하는 것이다. 당시 제시된 지급액과 순발행액 자체를 다음 주나 매월 초에 반복 적용하지 않는다.

## 학습을 누적하는 방법

여기서 학습은 모델 가중치 변경이나 자동 기억을 뜻하지 않는다. **다음 작업자가 먼저 읽는 규칙과 실제 전후 사례를 저장소에 누적하고, 매번 작성 과정에 적용하는 방식**이다. 이 문서가 실행 지침이고, 주차별 원본·최종 문안은 근거다.

새 피드백을 받으면 문구만 고친 뒤 끝내지 않고 다음을 기록한다. 단, 사소한 오타마다 규칙을 늘리지 않는다. 기존 원칙으로 설명되면 그 원칙에 사례를 하나 추가한다.

| 기록 항목 | 남길 내용 |
|---|---|
| 날짜와 대상 | 주차, 챕터, 블록 ID |
| 초안 | 사용자가 수정하기 전의 문구 또는 보존 파일 |
| 사용자 요청 | 삭제·축약·추가·이동·유지·데이터 기준 변경 중 무엇인지, 필요한 직접 인용 |
| 최종 반영 | 실제 적용 문구, 원문과 다르게 정정한 부분 |
| 근거와 작성 주체 | 사용자 조사인지 AI 분석인지, 수치 확인 자료와 기준일 |
| 외부 조사 | 조사 질문, 확인한 출처·공개일·사건일, 확인된 원인과 미확인 가설, 본문에 채택한 내용 |
| 적용 범위 | 특정 주차 / 특정 지표 / 공통 문체 / UI / 데이터 계산 |
| 학습 상태 | 명시 지시 / 추론한 선호 / 일회성 결정 / 폐기됨 |
| 다음 작성 행동 | 무엇을 다르게 할지 한 문장. 해당하지 않는 경우도 함께 기록 |

규칙을 갱신할 때는 같은 의미의 규칙을 계속 추가하지 말고 기존 항목을 수정한다. 사용자 지시가 바뀌면 이전 규칙을 조용히 삭제하기보다 변경 이력에 남긴다. 예를 들어 “스티키 전부 제거”는 이후 “주차 헤더만 스티키”로 범위가 바뀌었다.

월별·분기별 새 관측이 나오면 이전의 ‘해설 생략’을 재검토한다. 삭제는 과거 시점의 편집 판단이고 새로운 정보를 무시하라는 지시가 아니다. 반대로 새 관측이 없는데 삭제한 해설을 문구만 바꾸어 복원하지 않는다.

### 손이 덜 가는지 확인할 항목

- 사용자가 고친 블록 중 반복 정의·수치 나열 때문에 줄인 블록은 얼마나 되는가.
- 부호·단위·비교 기간·만기 오류가 있었는가. 이는 문체 수정과 별도로 집계한다.
- 전주에 남긴 질문에 답했는가. 사용자에게 같은 배경을 다시 설명하게 했는가.
- 위치 이동이나 문단 분리 요청이 반복되는가.
- 명시적으로 삭제한 내용을 다시 넣었는가.
- 새로운 해석을 사용자가 추가해야 했는가, 아니면 AI가 제안한 해석을 선택·축약하는 수준이었는가.
- 핵심 변화에서 사용자가 외부 원인을 직접 찾아 제공해야 했는가. AI가 조사한 배경은 실제 해당 주간을 설명했는가.
- 수치 나열·지나친 용어 축약 때문에 사용자가 문장을 다시 풀어 써야 했는가. 줄인 문장에서 비교 기준이 사라지지는 않았는가.

수정량을 무조건 줄이는 것만 목표로 삼지 않는다. 빈 초안을 제출해 수정할 것이 없는 상태는 개선이 아니다. 수치·기간 오류 없이, 유용한 새 해석을 먼저 제안하면서 불필요한 편집을 줄이는 것이 목표다.
